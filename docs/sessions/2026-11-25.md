## Conversation

1. User asked how to launch. The machine had no `.venv` and only Python 3.6–3.9; installed Python 3.12.10 via winget (user approved a UAC prompt), created `.venv`, installed the project, launched.
2. User asked to make it more of a game. Proposed pressure options; user redirected: the complexity should be in *building* a process (reactor, splitter, pumps, purification string) that turns a defined starting feed into a target amount of product. Single level was fine at first.
3. Proposed a single reactor/separator/recycle/purge puzzle. User rejected it as too fixed: wants more randomness, a roguelike with no single optimal answer, multiple reactions (A→B, B→C, A+B→C, ...), and levels that build on the existing plant.
4. Agreed design (now in DESIGN.md): random reaction chain per run, escalating contracts with thresholds, plant persists, 3 attempts per contract, draft 2 of 5 between contracts with the new reactor granted free.
5. Built it: rewrote `sim/` (Stream, chemistry, new units, push-based flow with spills), added `run/` (contracts, RunState), new `content/` dealing, new play scene (build/run/result modes, tooltips, speed control) and draft scene.

6. Committed on branch `roguelike-contracts` (fb8fb89).
7. User shared a dark DCS screenshot and asked for a gamified version of that look: icons on inventory cards, no instant pass/fail after RUN (run it live, tweak settings, figure it out), pump flow ranges to tune, one color per chemical with streams/pipes showing the blended color.
8. Built it: dark theme with shaded vessels, icon cards, colored pipes with moving flow dots, faceplate + wheel tuning, pump setpoint ranges, continuous splitter, per-stream on-spec grading at PRODUCT, live completion, restarts instead of attempts. Added reactor/column rated GPM with overload penalties so tuning has a sweet spot (my addition to give the ranges meaning).
